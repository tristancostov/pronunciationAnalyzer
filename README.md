# Анализатор произношения русского языка

Система оценки произношения русской речи: распознаёт слова по аудио,
делит слова на слоги, локализует слоги в сигнале, определяет ударение
(словарное + акустическое), оценивает редукцию безударных гласных и
сравнивает реально произнесённое с эталонным текстом. Имеет встроенный
аппарат оценки точности: ручная разметка границ слогов в Praat
сравнивается с автоматическим выходом, что даёт объективные метрики.

## Главные результаты (на текущей выборке)

- **Точность границ слогов**: медианная ошибка **25–30 мс** на всех трёх
  размеченных записях (3local, 6fori, 7fori). Это близко к порогу
  различимости границ человеческим ухом.
- **Точность определения числа слогов в слове**: **95% у носителей**
  (3local), **80% у неносителей** (6fori, 7fori). Разница согласуется
  с реальностью: у неносителей чаще встречается выпадение/слияние
  слогов, которое система фиксирует.
- **Редукция гласных** (статистически строгая проверка t-тестом Уэлча,
  минимум 10 образцов в группе): в 4 из 6 записей носителей значимо
  (p<0.05, часто p<0.01) подтверждена редукция «о» в предударной
  позиции — классическое русское аканье. Отношения длительностей
  безударный/ударный = 0.72–0.77.

## Используемые технологии

| Назначение | Инструмент |
|---|---|
| Распознавание речи (offline) | VOSK, модель `vosk-model-ru-0.42` |
| Морфологический анализ | pymorphy2 |
| Словарное ударение | ruaccent |
| Акустические признаки | librosa: MFCC, MEL-спектр, RMS, ZCR, форманты (LPC) |
| Основная частота (F0) | librosa.pyin (вероятностный YIN) |
| Сигнальная обработка | scipy.signal — `find_peaks`, фильтр Баттерворта |
| Сравнение текста | difflib (`SequenceMatcher`) |
| Конвертация аудио | ffmpeg → 16 кГц / моно / PCM 16-бит |
| Ручная разметка эталона | Praat (TextGrid, UTF-16) |
| Статистические тесты | t-тест Уэлча и 95% ДИ (без scipy, через регуляризованную бету) |

### Ключевые алгоритмы

- **Слогоделение** — по принципу восходящей звучности (адаптация
  алгоритма с Хабра), применяется к произнесённой форме слова.
- **Поиск ядер слогов** — метод de Jong & Wempe + взвешивание
  «гласности» каждого кадра по MEL-спектру и MFCC: подавляет ложные
  пики на звонких согласных (р/м/н/л) и выделяет настоящие гласные.
- **Размещение границ** — в минимумах энергии между ядрами (пробовали
  взвешивать на MFCC/Delta MFCC — ухудшает медианную ошибку, поэтому
  оставлена чистая энергия).
- **Определение ударения, двойная схема:**
    - `expectedStressedIdx` — по словарю ruaccent (норма);
    - `actualStressedIdx` — по акустике: F0 + длительность + энергия +
      F1 + «открытость» по MFCC. Несовпадение этих двух значений
      указывает на возможную ошибку произношения у неносителя.
- **Анализ редукции** — статистика по всей записи: гласные группируются
  по позиции относительно ударного (предударный / заударный / прочие
  безударные) и сравниваются с ударной группой по длительности и
  централизации формантной точки до нейтрального [ə]. Значимость —
  t-тестом Уэлча.

## Данные

13 записей в `audio/` с парными эталонными текстами в `text/`. По именам:

- **`*local`** — речь носителей русского языка (фрагменты из видеоблогов
  с известным текстом). 6 записей (1local…6local).
- **`*fori`** — речь неносителей (китайские учащиеся MGU). 7 записей:
  - 1fori, 6fori, 7fori — чтение стандартного набора из 11 фраз
    (читают одно и то же, удобно сравнивать);
  - 2fori–5fori — спонтанные доклады по своим текстам.

**Ручная разметка слогов в Praat** есть для трёх записей:
- 3local (40 слов, носитель — даёт верхнюю границу точности),
- 6fori и 7fori (~43 и ~42 слова, неносители — основная цель оценки).

Остальные записи используются для статистического анализа редукции
(не требует ручной разметки — нужны только JSON с акустическими
признаками каждого слога).

## Подготовка аудио

VOSK работает на **16 кГц / моно / 16-бит PCM**. Конвертация:

```
ffmpeg -i вход.wav -ar 16000 -ac 1 -c:a pcm_s16le audio/имя.wav
```

## Запуск

### 1) Анализ записи

В начале `pronunciationAnalyzer.py` указать имя файла:
```python
audioFile = os.path.join(SCRIPT_DIR, "audio", "имя.wav")
textFile  = os.path.join(SCRIPT_DIR, "text",  "имя.txt")
```
Запустить — получим `analysis/имя_syllable_analysis.json` и
консольный отчёт.

### 2) Ручная разметка эталона в Praat (для оценки точности)

1. `Open → Read from file...` → `audio/имя.wav`.
2. `Annotate → To TextGrid...` → tier name: `syllable`.
3. Выделить Sound + TextGrid → `View & Edit`.
4. Расставить границы каждого слога, вписать текст по фактическому
   произношению (если носитель что-то слил/опустил — фиксируем как
   услышали).
5. `Save → Save as text file...` → `analysis/имя.TextGrid`.

### 3) Сверка с разметкой и метрики

В `ground_truth_words.json` добавить ожидаемый список слов (имя,
число слогов) для новой записи. В `evaluate_annotations.py` указать
`RECORDINGS = ["имя", ...]` или оставить `[]` для автообнаружения.
Запустить — получим `evaluation_results.csv` + `.md`.

### 4) Кросс-записной анализ редукции

Запустить `reductionAnalysis.py`. Скрипт находит все
`*_syllable_analysis.json`, группирует слоги по гласному и позиции,
сравнивает безударные группы с ударной t-тестом Уэлча, строит
таблицу `reduction_comparison.md`.

### 5) Нарезка слогов в отдельные .wav (опционально, для слухового
контроля точности границ)

```
python extraSegAudio.py
```

## Метрики оценки

| Метрика | Что измеряет |
|---|---|
| **SylCountAcc** | Доля слов с правильным числом слогов (vs ручной разметки). |
| **Boundary error** | Абсолютная разница (мс) границ слогов: ручная vs автоматическая. Считается только по словам с совпавшим числом слогов. Приводятся среднее, медиана и 90-й перцентиль. |
| **StressAcc (акустика)** | Доля многосложных слов, в которых акустический детектор ударения совпал с самым длинным слогом в ручной разметке. |
| **StressAcc (словарь)** | То же, но для словарного (ruaccent) ударения. Разница между этими двумя метриками — индикатор ошибок ударения у говорящего. |
| **Reduction ratio (длит./центр.)** | Среднее отношение безударный/ударный для гласного V в позиции P. <1 = редукция. Значимость — t-тест Уэлча. |

## Обозначения в консольном отчёте анализатора

- `´` после слога — ударный (по словарю).
- `[ядер:N≠слогов:M]` — пометка неуверенности в границах: акустика
  нашла N ядер, а в тексте M слогов. Сегментов в выходе всё равно
  будет M, но часть границ может быть приближённой.
- `↻` — замечание по редукции.

## Ограничения и направления развития

- Медианная ошибка нарезки слогов (25–30 мс) сопоставима с величиной
  редукции «а», «е», «и» в быстрой речи носителей — поэтому редукция
  этих гласных не всегда выходит на статистическую значимость
  на текущем размере выборки. Уверенно фиксируется только «о»
  в предударной позиции.
- Для уточнения редукции остальных гласных и для повышения точности
  определения ударения требуется фонемное выравнивание (например,
  через MFA), потому что длительность слога целиком включает
  согласные, которые редукции не подвергаются и «размывают» сигнал.
- Стресс-метрика частично ограничена приближением «самый длинный слог
  = ударный» в ручной разметке; для более точной оценки нужно
  отдельно размечать ударный слог.
