Ключевые алгоритмы:

Слогоделение — по принципу восходящей звучности (адаптация
алгоритма с Хабра), применяется к произнесённой форме слова.
Поиск ядер слогов в аудио — метод de Jong & Wempe: энергия в
низкочастотной полосе гласных (≤ 1000 Гц), голосовой фильтр (исключение
глухих согласных), пики с порогом энергетического провала; число ядер
согласуется с известным из текста числом слогов.
Анализ редукции — внутреннее сопоставление слогов: безударные слоги
сравниваются с ударным по длительности, энергии и формантной
централизации (смещение F1/F2 к центру гласного пространства).
Оценка точности — сверка автоматического выхода с ручной слоговой
разметкой эталона в Praat: точность числа слогов, ошибка границ (мс),
точность определения ударения.

Папки

audio/ — все входные записи в правильном для VOSK формате
(16 кГц, моно, 16-бит PCM). Имя файла соответствует имени текста в
text/ (например, audio/1fori.wav ↔ text/1fori.txt).
text/ — эталонные тексты: то, что говорящий должен был
произнести. Используются для сравнения с распознанным и для
слогоделения.
vosk-model-ru-0.42/ — распакованная модель распознавания
(содержит am/, conf/, graph/, ivector/, rescore/, rnnlm/).
syllables_export*/ — результат работы extraSegAudio.py: каждый
файл внутри — это один вырезанный слог в формате WAV; имя вида
NN_слово_слог.wav. Используются для проверки на слух точности
слоговых границ.

Основные скрипты

pronunciation_analyzer.py — основной скрипт. На вход принимает
один аудиофайл и его текст (пути заданы в начале файла), на выход даёт
консольный отчёт и JSON-файл с полным разбором.
extraSegAudio.py — берёт готовый <имя>_syllable_analysis.json,
по сохранённым временны́м меткам слогов вырезает соответствующие
фрагменты из исходного WAV и сохраняет их в папку syllables_export*/.
evaluate_annotations.py — сравнивает ручную разметку Praat
(<имя>.TextGrid) с автоматическим выходом системы
(<имя>_syllable_analysis.json) и считает три ключевые метрики:
точность числа слогов, ошибку границ слогов в мс и точность
определения ударения.

Конфигурационные файлы

ground_truth_words.json — для каждой размеченной записи задаёт
ожидаемый список слов и число слогов в каждом. Чтобы добавить новую
размеченную запись, редактируйте этот файл, не Python-код.

Файлы результатов

<имя>_syllable_analysis.json — основной результат анализа одной
записи. Содержит: распознанный и эталонный текст; пословный разбор
(wordAnalysis) с временны́ми метками, слогами, их границами в аудио,
акустическими признаками (энергия, форманты), ударным слогом и
анализом редукции; таблицу контраста слогов ударный/безударный
(syllableContrast); ошибки на уровне слов и слогов
(wordComparison, syllableErrors); паузы.
<имя>.TextGrid — ручная разметка слоговых границ в формате
Praat (UTF-16). Служит эталоном (ground truth) для оценки точности
системы.
evaluation_results.md / .csv — итоговая таблица метрик после
запуска evaluate_annotations.py.

Данные и источники
Записи разделены на две группы (отражено в именах файлов):

*fori* — речь неносителей (китайцы). Включает: 1fori, 6fori,
7fori — чтение заранее заданного набора из 11 фраз (см. ниже);
2fori, 3fori, 4fori, 5fori — спонтанные доклады по тексту
(длинные записи с произвольным содержанием).
*local* — речь носителей русского языка. Фрагменты вырезаны из
видеоблогов (vlog). Исключение: 1local — говорящий из Киргизии
(неноситель, с акцентом).

Стандартный набор тестовых фраз (используется для записей
6fori, 7fori и т. д. — однотипный текст у всех неносителей):

Сегодня хорошая погода. Молоко стоит на столе. Маша читает книгу дома.
Студенты учатся в университете. Цена этого цветка высокая. Щука плавает
в озере. Я люблю русский язык. Вчера было очень холодно. Они работают
каждый день. Здоровье — это самое главное. Спасибо большое за помощь.

Важное замечание по части данных. Записи 2fori и 3fori
содержат спонтанные доклады, частично не соответствующие заданному
тексту (говорящие добавляли свои слова). Эти записи пригодны для
анализа свободной речи, но не подходят для оценки слоговых границ
по эталонному тексту.
Подготовка аудио (обязательно)
VOSK корректно работает только на формате 16 кГц, моно, 16-бит PCM.
Приведение из любого формата одной командой:
ffmpeg -i входной_файл -ar 16000 -ac 1 -c:a pcm_s16le audio/имя.wav
Запуск
1. Анализ записи

Положить запись в audio/, её текст — в text/ (с одинаковым именем).
В начале pronunciation_analyzer.py указать имена файлов:

python   audioFile = os.path.join(SCRIPT_DIR, "audio", "имя.wav")
   textFile  = os.path.join(SCRIPT_DIR, "text",  "имя.txt")

Запустить анализ:

   python pronunciation_analyzer.py
На выходе — консольный отчёт и имя_syllable_analysis.json.
2. Нарезка слогов в отдельные WAV (опционально)
python extraSegAudio.py
Создаёт папку syllables_export*/ с по-слоговыми WAV.
3. Ручная разметка эталона в Praat (для оценки точности)
См. ANNOTATION_GUIDE.md — пошаговая инструкция. Кратко:

В Praat: Open → Read from file... → имя.wav.
Выделить аудио → Annotate → To TextGrid... → tier name: syllable.
Выделить Sound и TextGrid → View & Edit.
Расставить границы каждого слога (Enter), вписать текст слога
(по фактическому произношению).
Сохранить: Save → Save as text file... → имя.TextGrid.

4. Сверка с ручной разметкой и расчёт метрик

В ground_truth_words.json добавить ожидаемый список слов
и числа слогов для новой записи (если её ещё нет).
В начале evaluate_annotations.py указать список записей:

python   RECORDINGS = ["6fori", "7fori"]    # либо [] для автообнаружения

Запустить:

   python evaluate_annotations.py
На выходе — evaluation_results.md и evaluation_results.csv.
Метрики оценки
МетрикаЧто измеряетSylCountAccДоля слов, в которых система выдала правильное число слогов.Bound.err (mean / median / P90)Абсолютная разница (мс) границ слогов в разметке и в системе. Считается только по совпавшим по числу слогов словам.StressAccДоля многосложных слов, в которых ударный слог системы совпал с самым длинным слогом в ручной разметке (приближение).
Обозначения в отчёте анализатора

´ после слога — ударный слог.
[ядер:N≠слогов:M] после слова — сниженное доверие к границам:
акустически найдено N ядер при M слогах в тексте. Сегментов в выводе
всегда столько, сколько слогов; пометка указывает, что часть границ в
этом слове поставлена приближённо.
↻ — замечание по редукции (безударный слог недостаточно отличается
от ударного).
