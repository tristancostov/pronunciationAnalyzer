# Анализатор произношения русского языка

Настольный прототип приложения для анализа русской речи. Пользователь
записывает речь с микрофона или выбирает обычный аудио/видеофайл; приложение
само приводит сигнал к формату анализа, распознаёт слова, делит их на слоги,
локализует слоги в сигнале и показывает ударение, редукцию, темп и паузы.
Ручная конвертация в WAV и загрузка отдельного `.txt` не нужны.

Приложение поддерживает два методологически разных сценария:

- **Свободная речь** (режим по умолчанию): эталонного текста нет, интерфейс
  показывает автоматическую расшифровку и только безреференсные
  диагностические признаки. `wordAccuracy` в JSON равен `null`, а не 0%.
- **Тренировка по фразе приложения:** приложение само предлагает фразу,
  поэтому пользователю не надо готовить текстовый файл. Здесь дополнительно
  измеряется совпадение распознанных слов с заданием.

Для исследования точности ручная разметка границ слогов в Praat по-прежнему
сравнивается с автоматическим выходом. Эта разметка нужна разработчику для
валидации алгоритма, но не конечному пользователю.

## Главные результаты (на текущей выборке)

- **Распознавание свободной речи:** на 13 записях / 1541 слове переход от
  VOSK-текста к Whisper `large-v3-turbo` снизил micro-WER с **29,40%**
  до **12,98%**. На трёх вручную размеченных записях / 186 словах —
  с **11,83%** до **4,30%**. Эталон не передавался распознавателю и
  использовался только после распознавания для вычисления WER.
- **Гибридные временные метки:** Whisper определяет слова, VOSK даёт более
  точные временные якоря. На трёх размеченных записях это сохранило
  AcousticNucleiAcc **60,5%** и медианную ошибку границ **28,9 мс**;
  прямые Whisper timestamps давали лишь 34,7% и 89,3 мс соответственно.
- **Точность текстового слогоделения**: **94,4%** (118/125 слов). Эта
  метрика проверяет лингвистический алгоритм по написанию слова, а не
  акустический детектор. Исправлена обработка соседних гласных
  (`видео → ви-де-о`, `организации → ор-га-ни-за-ци-и`).
- **Точность числа акустически найденных ядер V1**: **60,8%** (76/125 слов)
  после калибровки на трёх размеченных записях; до калибровки было
  **52,0%** (65/125). По записям: 57,5% (3local), 65,1% (6fori),
  59,5% (7fori). Это честная метрика текущего главного ограничения.
- **Акустические ядра V2/V3:** после уточнения ручной разметки честная
  grouped-оценка V2 на 3local/6fori/7fori составляет **F1 83,42%**.
  После добавления вручную проверенного 17,43-секундного фрагмента нового
  говорящего четырёхгрупповая оценка V3 составляет **F1 88,49%** без текста
  и **Precision 92,63%, Recall 87,71%, F1 90,10%** с консервативной
  фильтрацией по собственным ASR-токенам приложения. Пользователь не вводит
  эталонный текст. Однократный ранее запечатанный blind test 8fori дал
  **Precision 80,77%, Recall 81,55%, F1 81,16%** при ±50 мс; этот более
  слабый результат сохранён и показывает необходимость новых независимо
  центрированных ручных данных.
- **Точность границ слогов**: общая медианная ошибка **28,8 мс**
  (по записям 24,6 / 31,5 / 29,7 мс). Границы считаются только для слов,
  где текстовое число слогов совпало с ручной разметкой.
- **Редукция гласных** (статистически строгая проверка t-тестом Уэлча
  с Cohen's d, минимум 10 образцов в группе): в 4 из 6 записей носителей
  значимо (p<0.05, часто p<0.01) подтверждена редукция «о» в предударной
  позиции — классическое русское аканье. Отношения длительностей
  безударный/ударный = 0.73–0.76 (по вокалическому ядру).
  - На записи **5local** — наиболее полная картина: редукция «о» значима
    во всех трёх безударных позициях (p<0.01 для предударной и заударной,
    p<0.001 для прочих безударных), плюс значимая централизация (p<0.05)
    — двойное доказательство редукции по длительности И по качеству гласного.
  - **Централизация** (расстояние F1/F2 до [ə]) достигает значимости
    в отдельных случаях: 5local (о), nonnative_pooled (о), 4local (и).

Важно: единый «балл качества произношения» больше не вычисляется.
Сегментируемость, совпадение ударения, редукция, темп и точность STT
выводятся раздельно, потому что без нормирования по типу речи их сумма
даёт методологически неверное сравнение медленного чтения и быстрого монолога.

## Используемые технологии

| Назначение | Инструмент |
|---|---|
| Распознавание речи (offline) | Whisper `large-v3-turbo` (текст) + VOSK `ru-0.42` (временные якоря) |
| Морфологический анализ | pymorphy2 |
| Словарное ударение | ruaccent |
| Акустические признаки | librosa: MFCC, MEL-спектр, RMS, ZCR, форманты (LPC) |
| Основная частота (F0) | librosa.pyin (вероятностный YIN) |
| Сигнальная обработка | scipy.signal — `find_peaks`, фильтр Баттерворта |
| Сравнение текста | difflib (`SequenceMatcher`) |
| Конвертация аудио | ffmpeg → 16 кГц / моно / PCM 16-бит |
| Ручная разметка эталона | Praat (TextGrid, UTF-16) |
| Статистические тесты | t-тест Уэлча и 95% ДИ (без scipy, через регуляризованную бету) |

### Ключевые алгоритмы

- **Слогоделение** — по принципу восходящей звучности: каждая гласная
  образует отдельный слог, а граница в кластере согласных ставится перед
  максимальным суффиксом с возрастающей звучностью. Применяется к
  произнесённой форме слова.
- **Поиск ядер слогов** — метод de Jong & Wempe + взвешивание
  «гласности» каждого кадра по MEL-спектру и MFCC: подавляет ложные
  пики на звонких согласных (р/м/н/л) и выделяет настоящие гласные.
  Параметры поиска калибруются скриптом `calibrate_nuclei.py`; MEL/MFCC
  участвуют в ранжировании кандидатов, но не искажают raw-count пиков.
- **Размещение границ** — в минимумах энергии между ядрами.
- **Локализация вокалического ядра** — внутри каждого слога выделяется
  чисто гласный сегмент по MEL-контрасту (F1-область vs высокие частоты),
  низкочастотной энергии и ZCR. Признаки редукции считаются по ядру,
  а не по слогу целиком — это устраняет «размывание» сигнала согласными.
- **Определение ударения, двойная схема:**
    - `expectedStressedIdx` — по словарю ruaccent (норма);
    - `actualStressedIdx` — по акустике: F0 + длительность + энергия +
      F1 + «открытость» по MFCC. При наличии вокалического ядра
      длительность и F1 берутся от ядра, а не от целого слога.
      Несовпадение этих двух значений указывает на возможную ошибку
      произношения у неносителя.
    - `ё` обрабатывается как однозначно ударная гласная; поддерживаются
      оба формата метки ruaccent (`+` перед гласной и combining acute после).
- **Анализ редукции** — статистика по всей записи: гласные группируются
  по позиции относительно ударного (предударный / заударный / прочие
  безударные) и сравниваются с ударной группой по длительности и
  централизации формантной точки до нейтрального [ə]. Значимость —
  t-тестом Уэлча, размер эффекта — Cohen's d.

## Данные

13 записей в `audio/` с парными эталонными текстами в `text/`. По именам:

- **`*local`** — речь носителей русского языка (фрагменты из видеоблогов
  с известным текстом). 6 записей (1local…6local).
- **`*fori`** — речь неносителей (китайские учащиеся MGU). 7 записей:
  - 1fori, 6fori, 7fori — чтение стандартного набора из 11 фраз
    (читают одно и то же, удобно сравнивать);
  - 2fori–5fori — спонтанные доклады по своим текстам.

**Ручная разметка слогов в Praat** есть для трёх записей:
- 3local (40 слов, носитель — даёт верхнюю границу точности),
- 6fori и 7fori (~43 и ~42 слова, неносители — основная цель оценки).

Остальные записи используются для статистического анализа редукции
(не требует ручной разметки — нужны только JSON с акустическими
признаками каждого слога).

## Входные данные приложения

GUI принимает запись с микрофона и файлы WAV, MP3, M4A, FLAC, OGG, AAC,
WebM, MP4, MOV и MKV. Модуль `audio_input.py` автоматически создаёт
кешированную копию **16 кГц / моно / 16-бит PCM** через ffmpeg. Исходный
файл не изменяется. Если WAV уже подходит, он используется напрямую.

## Запуск

### 1) Запуск настольного приложения

Можно дважды щёлкнуть `run_app.cmd` или выполнить:

```powershell
Python\Python39\python.exe gui_app.py
```

1. Оставить режим **«Свободная речь»** или выбрать **«Тренировка по фразе»**.
2. Нажать **«Записать»** либо выбрать аудио/видеофайл.
3. Нажать **«Анализировать»**. Расшифровка и диагностические признаки
   появятся в интерфейсе, JSON — в `analysis/`.

По умолчанию выбран `whisper`: Whisper отвечает за текст, а VOSK — за
временные якоря слов. Режим `vosk` оставлен как более лёгкий резервный вариант.

Программный вызов без эталонного текста:

```python
import pronunciationAnalyzer as pa
result = pa.main(inputAudio=r"C:\recordings\speech.m4a",
                 referenceText="", asrEngine="whisper")
print(result["jsonPath"])
```

Для режима тренировки передайте фразу приложения в `referenceText`. Значение
`None` оставлено только для обратной совместимости CLI: тогда читается
глобальный `textFile`, если он существует.

### 2) Ручная разметка эталона в Praat (для оценки точности)

1. `Open → Read from file...` → `audio/имя.wav`.
2. `Annotate → To TextGrid...` → tier name: `syllable`.
3. Выделить Sound + TextGrid → `View & Edit`.
4. Расставить границы каждого слога, вписать текст по фактическому
   произношению (если носитель что-то слил/опустил — фиксируем как
   услышали).
5. `Save → Save as text file...` → `analysis/имя.TextGrid`.

### 3) Сверка с разметкой и метрики

В `ground_truth_words.json` добавить ожидаемый список слов (имя,
число слогов) для новой записи. Запустить:

```
python EvaluateAnnotations.py 3local 6fori 7fori
```

Без имён скрипт автоматически найдёт все пары TextGrid + JSON. Получим
`results/evaluation_results.csv` + `.md`.

Для честной оценки ударения вручную отметьте ударный слог в TextGrid
знаком `+`, `´`, combining acute или буквой `ё` (например, `к+о`).
Без явной отметки StressAcc не вычисляется.

### 3б) Калибровка детектора акустических ядер

```
python calibrate_nuclei.py 3local 6fori 7fori
```

Скрипт использует готовые временные метки VOSK (большую модель повторно
не загружает), перебирает параметры поиска пиков и отдельно показывает
leave-one-recording-out результат, чтобы не скрывать переобучение.

### 3в) Сравнение распознавателей без подсказки текстом

```powershell
Python\Python39\python.exe benchmark_asr.py 3local 6fori 7fori
```

Скрипт передаёт Whisper пустой prompt, а эталон читает только после
распознавания для вычисления Levenshtein WER. Результат сохраняется в
`results/asr_benchmark.md` и `.json`.

### 4) Кросс-записной анализ редукции

```
python reductionAnalysis.py
```
Находит все `*_syllable_analysis.json`, группирует слоги по гласному и позиции,
сравнивает безударные группы с ударной t-тестом Уэлча + Cohen's d,
объединяет неносителей в одну группу. Строит `reduction_comparison2.md`
и графики (forest plot + boxplot → `reduction_plots_*.png`).

### 5) Проверка детектора ударения

```
python check_stress.py
```
Сравнивает словарное ударение (ruaccent) с акустическим детектором
по всем записям. Вывод: консоль + `stress_check_report.md`.

### 6) Нарезка слогов в отдельные .wav (опционально)

```
python extraSegAudio.py              # все записи → syllables_export/имя/
python extraSegAudio.py 3local       # одна запись
python extraSegAudio.py --max 30     # максимум 30 слогов на запись
```

## Метрики оценки

| Метрика | Что измеряет |
|---|---|
| **TextSylAcc** | Доля слов, где алгоритм слогоделения текста дал правильное число слогов. |
| **AcousticNucleiAcc** | Доля слов, где raw-count акустически найденных ядер совпал с ручной разметкой. |
| **Boundary error** | Абсолютная разница (мс) границ слогов: ручная vs автоматическая. Считается только по словам с совпавшим числом слогов. Приводятся среднее, медиана и 90-й перцентиль. |
| **StressAcc (акустика)** | Доля многосложных слов, где акустический детектор совпал с явно отмеченным вручную ударным слогом. |
| **Dict↔Acoustic** | Совпадение ruaccent и акустики; диагностический proxy, не ground truth. |
| **Reduction ratio (длит./центр.)** | Среднее отношение безударный/ударный для гласного V в позиции P. <1 = редукция. Значимость — t-тест Уэлча. |

## Обозначения в консольном отчёте анализатора

- `´` после слога — ударный (по словарю).
- `[ядер:N≠слогов:M]` — пометка неуверенности в границах: акустика
  нашла N ядер, а в тексте M слогов. Сегментов в выходе всё равно
  будет M, но часть границ может быть приближённой.
- `↻` — замечание по редукции.

## Экспериментальный акустический детектор V2

`acoustic_nuclei_v2.py` реализует детектор слоговых ядер, который
принципиально не получает текст, число слогов или forced alignment. Он строит
адаптивный многополосный контур звучности, добавляет периодичность, спектральный
поток, ZCR и штраф за низкочастотный сонорный пик, а затем выбирает сильные и
редуцированные кандидаты с независимой оценкой уверенности. Замороженная
конфигурация `recall_4_noise_gate` встроена в основной анализатор.

В GUI столбец `Ядра V2 / V1 / текст` показывает три значения раздельно.
Фиолетовые вертикальные линии на осциллограмме — положения V2-ядер. V2
запускается один раз на всей записи и только после детекции его точки
группируются по временным интервалам распознанных слов для отображения.
Текст не добавляет и не удаляет V2-кандидаты. Сравнение с числом гласных в
распознанном слове — диагностическая информация, а не автоматический вердикт
об ошибке произношения.

Проверенная grouped-оценка на четырёх development recordings:

| Метод | Precision@50 | Recall@50 | F1@50 |
|---|---:|---:|---:|
| V3 text-independent | 87,88% | 89,11% | 88,49% |
| V3 + automatic-ASR vowel-count prune | 92,63% | 87,71% | **90,10%** |
| Замороженный 8fori blind test | 80,77% | 81,55% | **81,16%** |

Ранее опубликованные трёхзаписные значения V2 83,42%, text-independent V3
89,11% и ASR-assisted V3 90,00% сохранены в исследовательском протоколе как
история разработки, но не являются финальным blind-test результатом.

Подготовить неперезаписывающие исходную разметку Praat-файлы:

```powershell
Python\Python39\python.exe prepare_nucleus_annotations.py 3local 6fori 7fori
```

После ручной проверки сохранить файлы как
`analysis/v2_annotations/*_v2_reviewed.TextGrid`, затем запустить:

```powershell
Python\Python39\python.exe evaluate_nuclei_v2.py 3local 6fori 7fori
```

Оценка сообщает event Precision/Recall/F1 с допуском ±30 и ±50 мс. Интервалы
без написанной гласной, например отдельные `в` и `с`, не считаются акустическими
слоговыми ядрами. Инструкция по проверке находится в
`analysis/v2_annotations/README_校正说明.md`.

`acoustic_nuclei_v3.py` — воспроизводимый CLI для обучения и запуска V3.
Он объединяет precision-oriented V2, Sylber-сегменты и SVM по акустическим
признакам. Модель разработки сохранена в
`models/nuclei_v3_svm.joblib`; она обучена на 3local, 6fori, 7fori и коротком

## Ограничения и направления развития

- **Редукция «а», «е», «и»:** медианная ошибка нарезки слогов (25–30 мс)
  сопоставима с величиной редукции этих гласных в быстрой речи носителей.
  Локализация вокалического ядра частично решает проблему (изоляция
  гласного от согласных), но нужна бо́льшая выборка и более устойчивый
  поиск вокалического ядра без перехода к ненадёжному полному фонемному
  выравниванию.
- **Поиск акустических ядер:** V1 после калибровки достиг 60,8% совпадения
  числа ядер на словах. V2 существенно улучшил событийную локализацию, но
  пока проверен лишь на трёх записях; одинаковый текст у `6fori/7fori` не
  доказывает перенос на произвольную лексику, микрофоны и типы речи. Следующий
  этап — расширять независимую тестовую выборку, не подстраивая уже
  замороженную конфигурацию под каждый новый файл.
- **StressAcc пока не измерен честно:** совпадение акустики со словарём
  составляет 48,9%, но это только proxy. Правило «самый длинный слог =
  ударный» удалено из оценивания; нужно явно отметить ударение в TextGrid,
  после чего настраивать признаки F0/длительности/энергии на train-части
  и проверять на отдельных говорящих.
- **Свободная речь не даёт знания о намерении пользователя.** Если ASR
  распознал другое реальное слово, без задания невозможно узнать, была ли это
  ошибка произношения или именно это слово и было задумано. Поэтому GUI
  отдельно показывает расшифровку и confidence распознавателя, а не называет результат
  «точностью произношения».
- **WER неоднороден:** общий Whisper micro-WER равен 12,98%, но на записи
  4fori остаётся 61,33%. Это может отражать и тяжёлую речь/шум, и несовпадение
  предоставленного текста с фактически сказанным; перед заявлением итоговой
  точности нужно вручную проверить транскрипты и расширить тестовый набор.
- **Мобильная версия:** текущий tkinter GUI — настольный проверяемый прототип.
  Для мобильного клиента анализатор лучше вынести в локальный/серверный API,
  сохранив те же два режима и единый модуль подготовки аудио.
